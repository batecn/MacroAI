变化检测

"等待变化"节点是做什么的？和"等待"节点有什么区别？通用
  • 等待 — 固定等一段时间（如 2 秒），不管屏幕发生什么都等。"盲等"。
  • 等待变化 — 持续监控屏幕，直到指定区域画面发生变化才继续。"智能等"。

典型场景：

  • 等待加载完成 → 用"等待变化"监控加载动画区域，画面一变（加载结束）就继续
  • 等待对手出招 → 监控游戏画面，有变化就触发应对操作
  • 等待页面跳转 → 监控内容区域，变化说明跳转了

比"等待 3 秒"更智能：变化快就早执行，变化慢就自动多等，不会浪费时间也不会错过时机。

"等待条块变化"节点怎么用？需要上传多个模板是什么意思？通用

"等待条块变化"专门用于监控血条、进度条、能量条等条形元素的长短变化。

为什么需要多个模板？因为条块在不同长度时外观不同（满血是长条，残血是短条）。你需要截取同一血条在不同状态下的截图作为参照：

  1. 在节点配置中点击"取参考条块"
  2. 框选血条区域 → 输入名称（如"满血""低血"）
  3. 建议截取 2 张：1 张满血状态 + 1 张约 1/4 或 1/3 血量状态

注意：模板不宜太多，太多会影响检测效率。2 张已足够覆盖大多数场景。

引擎会持续匹配当前画面最接近哪个模板，当匹配结果从一个模板切换到另一个时，判定为"条块变化了"。

典型用法：监控角色血条，血量减少超过一定比例 → 自动使用药品。

条块变化的"变化阈值"和"匹配阈值"分别控制什么？通用

这两个阈值容易混淆，它们控制不同的事情：

  • 匹配阈值（默认 0.85）— 控制"当前画面和模板多像才算匹配上了"。和普通图像查找的阈值含义相同。太低会误匹配，太高会匹配不上。
  • 变化阈值（默认 0.1）— 控制"条块长度变化多少才算真的变了"。0.1 表示长度变化超过 10% 才报告。防止画面轻微抖动导致频繁误报。

简单记忆：匹配阈值管"找不找得到"，变化阈值管"变了多少才算变"。

一般保持默认即可。如果血条微调就误报 → 加大变化阈值到 0.15~0.2。

我想监控游戏血条变化自动吃药，应该怎么配置？通用

完整步骤：

  1. 添加循环节点（无限循环），让脚本持续监控
  2. 在循环内添加等待条块变化节点：
    • 区域：框选血条所在位置
    • 模板：截取 1 张满血 + 1 张低血（约 1/4）状态的参考图
    • 超时：设 0（持续监控直到变化）
    • 变化阈值：0.1（默认即可）
  3. 在等待条块变化后面添加条件判断：判断 delta（变化比例）是否表示血量减少
  4. 条件满足时添加查找图像节点：找到药品图标并点击
  5. 添加一个短等待（如 500ms），防止连续触发

这样脚本会持续监控血条，一旦检测到血量明显减少就自动点击药品。

参考示例：Windows 版内置了"游戏辅助-血条监控"Demo 项目，可通过菜单导入 Demo 包查看完整配置（包含 2 个模板：满血 + 30% 血量）。

录制与回放

如何录制一个宏？通用

Windows 版：

  1. 切换到"宏管理"标签页（Ctrl+7）
  2. 点击 + 新建录制
  3. 屏幕出现绿色边框（标示设计区域），左下角有"■ 停止录制"按钮
  4. 正常操作你想自动化的步骤（点击、打字等）
  5. 完成后点击"■ 停止录制"
  6. 选择"保存到项目"

Android 版：在编辑器中切换到录制模式，操作会被全屏覆盖层拦截并记录，同时底层界面会同步执行你的操作。

录制完成后，在宏列表中可以回放测试，也可以通过"调用录制宏"节点嵌入主流程。

录制时为什么有些操作没有被录进去？通用

MacroAI 录制时只记录设计区域内的操作。这是有意设计，防止你误操作（如点击了 MacroAI 自身的界面）被录进去。

没被录入的情况：

  • 点击了设计区域外面的位置（边框会闪红色提示）
  • 点击了 MacroAI 自身的窗口/按钮
  • Android 版：点击了录制浮球区域

解决办法：

  • 确保你的操作都在绿色边框范围内
  • 如果目标窗口比设计区域大，需要重新创建项目或修改设计区域
  • 看到边框闪红色 = 这次操作没被录入，需要重做
录制的宏回放时速度太快/太慢怎么办？通用

宏回放会保留录制时的时间间隔。如果你录制时操作很快，回放也会很快。

调整方法：

  • 录制时故意放慢节奏，每步之间留出足够间隔
  • 如果某步操作需要等加载，在录制时真的等到加载完再操作下一步
  • 录制完成后不能修改延时，如果不满意需要删除后重新录制

更好的做法：对于需要精确控制节奏的场景，建议用节点编辑器手动搭建（等待节点 + 点击节点），而不是依赖录制。录制更适合"操作序列固定、间隔不重要"的场景。

录制的宏能编辑吗？能加入条件判断吗？通用

宏本身不能编辑。录制完成后，你可以重命名、修改描述、回放、删除，但不能修改宏内部的具体事件（不能删除某个点击、不能调整延时、不能改坐标）。

录错了怎么办？删除后重新录制。

想要条件判断？用节点编辑器：

  1. 在节点编辑器中添加"调用录制宏"节点，选择你的宏
  2. 在它前后添加条件判断、循环、图像查找等节点
  3. 这样宏负责"执行操作"，节点编辑器负责"控制逻辑"

也可以把一个长操作拆成几段短宏分别录制，中间用节点逻辑连接，更灵活。

Android 版录制和 Windows 版有什么不同？Android

主要区别：

  • 操作类型：Android 录制的是触摸操作（点击、滑动），没有键盘输入（安卓键盘输入通过输入法，无法直接拦截）
  • 录制方式：Android 用全屏覆盖层拦截触摸事件，同时在底层回放（你能看到自己的操作效果）
  • 回放方式：通过无障碍服务的 dispatchGesture 注入手势，不需要 root
  • 限制：录制时不能操作状态栏/导航栏区域；多指手势（如缩放）暂不支持

因此 Android 版更推荐用节点编辑器搭建流程，录制作为辅助手段。Windows 版录制功能更完整（支持键盘、中文输入法）。
